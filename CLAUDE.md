# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

SPItFIRE is an analogue joystick and quadrature mouse adapter for the Acorn BBC Master Compact. The Master Compact lacks the analogue port found on other BBC Micros, so SPItFIRE adds it back: an ATMega1284p microcontroller acts as an SPI slave that the BBC reaches via a bit-banged SPI protocol on the 6522 VIA exposed at the Compact's Mouse/Joystick DE-9 port. The AVR reads analogue joysticks (ADC), keypads, and quadrature mice and reports state on demand.

## Repository Layout

- `firmware/` - ATMega1284p C++ firmware (multiple standalone executables, see Build Targets below)
- `beeb/spitest/` - 6502 BBC Micro test programs (SPITEST, SPIPERF, SPIMOUSE, etc.) - foreground utilities for proving each piece of hardware
- `beeb/rom/` - the SPItFIRE Sideways ROM (the eventual user-facing driver)
- `hardware/` - KiCad schematics and PCB
- `docs/` - design docs and datasheets (start with `protocol.md`, `spi-interface.md`, `peripheral-pinouts.md`)
- `docs/rom-design.md` - the in-progress ROM architecture proposal

## Build Commands

### Firmware (ATMega1284p)

```bash
cd firmware
cmake --preset release                       # Configure once
cmake --build --preset release --target <T>  # Build a specific target
cmake --build --preset release --target upload_<T>  # Flash to MCU
```

The firmware has **multiple standalone executables** built from different source files (each with its own `main()`). `CMakeLists.txt` excludes individual `*.cpp` files from each non-default target. Available targets:

| Target | Source | Purpose |
|--------|--------|---------|
| `spitfire` (default) | `main.cpp` + supporting files | Production joystick firmware |
| `spitest` | `spi_slave.cpp` | Minimal SPI slave (returns XOR pattern) |
| `spimouse` | `mouse.cpp` | Quadrature mouse firmware |

When adding a new standalone target, follow the pattern in `CMakeLists.txt`:
1. Add the source file to the exclude regex
2. Add an `add_executable(<name>)` block
3. Add a matching `upload_<name>` custom target

### BBC Micro Test Programs

```bash
cd beeb/spitest
make            # Build all programs
make SPIMOUSE   # Build a single program
```

Programs are saved as raw binaries plus `.inf` files for Econet/disk transfer. Load address is `&1900`. Naming convention: `SPI*` = bit-bang SPI, `SPIT*` = turbo SPI using VIA shift register.

### BBC Micro ROM

```bash
cd beeb/rom
make
```

Builds the Sideways ROM image. The ROM source is still under design - see `docs/rom-design.md`.

### Mouse Lookup Tables

The mouse firmware uses generated lookup tables in `firmware/src/mouse_tables.inc`. When mouse pinouts change, regenerate:

```bash
python3 firmware/tools/gen_mouse_tables.py firmware/src/mouse_tables.inc
```

Use `uv run --python 3.10` if your system Python is older than 3.10 (the script uses modern type-annotation syntax).

## Hardware Configuration

- MCU: ATMega1284p @ 18.432 MHz external crystal
- Programmer: USBasp
- Fuses: L=0xf7 (external crystal), H=0xd9, E=0xff

## Architecture Highlights

### Multi-device SPI Bus
A 74HC138 3-to-8 decoder expands three VIA pins (PB2-PB4) into 7 chip-select lines. Y0 = no device (idle), Y1 = SPItFIRE AVR; Y2-Y7 are reserved for future devices (RTC, SD card). Test programs select the AVR with `DEV_SPITFIRE = %00000100` written to IORB. The decoder's enable pins use the datasheet naming `G0`/`G1` (active low) and `G2` (active high).

### Two SPI Modes
- **Bit-bang** (~4100 bytes/sec): straightforward, used by all test programs
- **Turbo** (~7400 bytes/sec): uses VIA shift register in mode 3, CB1 wired externally to PB1 as a clock. MMFS-style; used by `SPIT*` test programs

### SPI Protocol
Single-byte commands with single-byte responses, two SPI bytes per command (command + dummy). See `docs/protocol.md`. Key ranges:
- `0x20`-`0x22`: joystick X/Y/buttons
- `0x30`-`0x32`: mouse dX/dY/buttons
- `0xF1`-`0xF3`: select mouse pinout mode (AMX/Amiga/Atari)

Mouse deltas are clamped to int8 and drained on read; large movements spread across consecutive polls.

### Mouse Decoding (non-obvious)
- Quadrature decoded by table-driven state machine in a pin-change ISR; tables generated by Python (see above).
- **Port D pin changes use the PCINT3 vector**, not PCINT2. The ATMega1284p datasheet calls Port D pins PCINT24-PCINT31, which is the PCINT3 group (PCMSK3/PCIE3/PCINT3_vect). The avr-libc macro names (`PCINT16`-`PCINT23` defined for PCMSK2) are misleading for this chip - **PCMSK2 is Port A on the 1284p**, not Port D.
- Decode tables index by `(prev << 4) | curr` of the 4-bit packed nibble `XA,XB,YA,YB`. Quadrature table columns must be in **numerical order** (00,01,10,11), not Gray code order (00,01,11,10) - a classic bug.
- Buttons read directly from PIND in the SPI handler, not the ISR.

### Standard BBC Mouse APIs
The ROM should implement standard BBC Micro mouse interfaces for ecosystem compatibility:
- `*MOUSE ON/OFF`, `ADVAL(7/8/9)`, `INKEY-10/-11/-12`, `OSWORD &40`
- SPItFIRE-specific configuration goes under a `*SPITFIRE <subsystem> ...` namespace (not `*MOUSE`)
- BBC graphics coordinates: **bottom-left origin**, 0-1279 X, 0-1023 Y. Text coordinates: top-left.
- See `docs/rom-design.md` for the full design proposal.

### Coordinate Conventions
The Amiga and Atari mouse pinouts in our `docs/peripheral-pinouts.md` use **native** Amiga/Atari conventions, not the BBC-adapted labelling used by mdfs.net (which swaps Y-axis labels to match BBC handedness). Don't cross-reference mdfs.net pinouts directly.

## Testing

This is embedded hardware - there is no automated test suite. Each piece of functionality is proven with a small standalone test program:
- Flash firmware → load BBC test program → exercise hardware → observe results on the BBC display.
- The `beeb/spitest/` programs are the regression suite. Re-run them after firmware changes.
- Build verification is "does it compile clean with `-Werror`" plus the size report from `avr-size`.

## Coding Conventions

- AVR firmware: C++17, `-Wall -Wextra -Werror -pedantic`. Anonymous namespaces for file-local state. PROGMEM for large tables.
- 6502 assembly: beebasm syntax. Standard BBC conventions for zero page (`&70`-`&8F`) and OS calls. Programs load at `&1900`.
- Pin-mapped lookup tables are auto-generated from Python - hand-editing the generated `.inc` files is wrong.
