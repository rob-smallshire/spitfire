# Mouse and Trackball Peripheral Design

## Overview

SPItFIRE reads quadrature mouse and trackball signals on AVR Port D, decodes
them into movement deltas, and reports the data over SPI to the BBC Micro.
This document describes the firmware architecture, SPI protocol, and BBC-side
test program.

## Architecture

```
Mouse/Trackball                 ATMega1284p                BBC Master Compact
───────────────                 ───────────                ────────────────────
  Quadrature     ──► Port D ──► Pin-Change ISR             Centisecond timer
  XA, XB,            (PD0-6)    ├─ remap[PIND]             ├─ SPI poll (100 Hz)
  YA, YB                       ├─ dx/dy lookup             │  ├─ CMD 0x30 → dX
  Buttons                      ├─ accumulate dx/dy         │  ├─ CMD 0x31 → dY
                               └─ read buttons             │  └─ CMD 0x32 → btns
                                        │                  ├─ accumulate totals
                               SPI Slave Main Loop         └─ display (10 Hz)
                                ├─ poll SPIF
                                ├─ clamp & drain accum
                                └─ return response
```

## Pin Remapping Architecture

Different mouse types use different signal-to-pin assignments on the Peripheral
DE-9. See [peripheral-pinouts.md](peripheral-pinouts.md) for full pinout tables.

### Remap Table Concept

Rather than testing individual pins in the ISR, a 128-byte lookup table converts
the raw PIND value directly into a packed 4-bit nibble:

```
Packed nibble: bit 0 = XA, bit 1 = XB, bit 2 = YA, bit 3 = YB
```

Each mouse type has its own remap table stored in flash (PROGMEM). The active
table is copied to SRAM for fast ISR access. Switching mouse type is a one-time
`memcpy_P()` of 128 bytes.

### Supported Modes

| Mode | XA | XB | YA | YB | Left | Right | Middle |
|------|----|----|----|----|------|-------|--------|
| Compact Mouse | PD4 | PD0 | PD6 | PD3 | PD5 | PD1 | PD2 |
| Amiga Mouse | PD1 | PD3 | PD2 | PD0 | PD5 | PD6 | PD4 |
| Atari Mouse | PD1 | PD0 | PD2 | PD3 | PD5 | PD6 | n/a |
| Bus Mouse | PD1 | PD2 | PD3 | PD4 | PD5 | n/a | n/a |
| Trackerball (adapter) | PD4 | PD5 | PD1 | PD6 | PD0 | PD3 | PD2 |

### Button Remap Tables

A separate 128-byte SRAM table maps PIND to a packed button byte
(bit 0=Left, bit 1=Right, bit 2=Middle, 1=pressed). Button pins are
active-low. Each mode has its own button table in PROGMEM.

### Table Generation

Tables are generated by `firmware/tools/gen_mouse_tables.py` and written to
`firmware/src/mouse_tables.inc`. This avoids error-prone manual computation
of 128-entry tables for each pinout.

## Quadrature Decoding

### State Machine

Each axis uses two signals (A and B) in Gray code:

```
Forward:  00 → 01 → 11 → 10 → 00  (A leads B by 90 degrees)
Reverse:  00 → 10 → 11 → 01 → 00  (B leads A by 90 degrees)
```

### Lookup Table Decode

Two universal 256-byte tables (`dx_table`, `dy_table`) in PROGMEM decode
both axes simultaneously. The index is `(prev_state << 4) | curr_state`
where each state is the 4-bit packed nibble from the remap table.

The 4x4 decode table per axis (numerical index order):

```
         curr: 00  01  10  11
prev 00:    0  +1  -1   0
     01:   -1   0   0  +1
     10:   +1   0   0  -1
     11:    0  -1  +1   0
```

Note: the columns and rows must be in numerical order (00, 01, 10, 11), not
Gray code order (00, 01, 11, 10), since the table is indexed numerically
by `(prev << 2) | curr`.

Invalid transitions (skipped states) return 0, providing natural debouncing.

### ISR Implementation

```cpp
ISR(PCINT3_vect) {
    uint8_t curr = remap[PIND & 0x7F];     // SRAM lookup: pins → nibble
    uint8_t idx = (prev_state << 4) | curr;
    dx_accum += (int8_t)pgm_read_byte(&dx_table_ptr[idx]);  // PROGMEM
    dy_accum += (int8_t)pgm_read_byte(&dy_table_ptr[idx]);  // PROGMEM
    prev_state = curr;
}
```

Buttons are read directly from PIND in the SPI command handler, not in the ISR.

**Important:** Port D on the ATMega1284P uses PCINT24-PCINT31, which is the
**PCINT3** group (PCMSK3/PCIE3/PCINT3_vect), NOT PCINT2 as one might assume
from the port letter. The mapping is:

| PCINT Group | Register | Vector | Port |
|-------------|----------|--------|------|
| PCINT0 | PCMSK0 | PCINT0_vect | Port B |
| PCINT1 | PCMSK1 | PCINT1_vect | Port C |
| PCINT2 | PCMSK2 | PCINT2_vect | Port A |
| PCINT3 | PCMSK3 | PCINT3_vect | Port D |

At 18.432 MHz, the ISR executes in approximately 2-3 us.

## Accumulator Model (Drain-on-Read)

### Concept

The AVR maintains 16-bit signed accumulators (`dx_accum`, `dy_accum`) that
are continuously updated by the ISR. When the BBC polls via SPI, the AVR:

1. Clamps the accumulator to [-127, +127]
2. Returns the clamped value as an int8
3. Subtracts the returned value from the accumulator

This means large movements are spread across consecutive polls:

```
Example: dx_accum = 300
  Poll 1: return +127, remaining = 173
  Poll 2: return +127, remaining = 46
  Poll 3: return +46,  remaining = 0
```

### Atomicity

The clamp-and-drain operation disables interrupts briefly to prevent the ISR
from modifying the accumulator mid-operation:

```cpp
cli();
int16_t val = dx_accum;
int8_t out = clamp(val, -127, 127);
dx_accum -= out;
sei();
```

### Why Not Velocity?

Serial mice established that **deltas** (not velocity) are the correct
abstraction. Velocity would require time normalisation and the host would
need to integrate anyway. Deltas decouple the AVR's continuous sampling from
the BBC's polling rate.

## SPI Protocol

Uses existing commands from [protocol.md](protocol.md):

| Command | Code | Response | Description |
|---------|------|----------|-------------|
| MOUSE_X | 0x30 | int8 | Clamped dX, drains accumulator |
| MOUSE_Y | 0x31 | int8 | Clamped dY, drains accumulator |
| MOUSE_BTN | 0x32 | uint8 | Button state (bit0=L, bit1=R, bit2=M) |
| MODE_AMX | 0xF1 | 0x01 | Switch to AMX/Compact pinout |
| MODE_AMIGA | 0xF2 | 0x02 | Switch to Amiga pinout |
| MODE_ATARI | 0xF3 | 0x03 | Switch to Atari pinout |

Mode switching loads the appropriate remap and button tables from flash to
SRAM and reconfigures the PCINT3 mask for the new quadrature pin assignments.
Accumulators are reset on mode change.

### Transaction Sequence

Each command requires two SPI byte transfers:

```
BBC sends command byte  → AVR reads command, prepares response, loads SPDR
BBC sends dummy (0x00)  → response clocked out to BBC
```

The BBC deselects (sets decoder to device 0) between commands.

A full mouse poll requires 3 commands = 6 SPI bytes. At ~4100 bytes/sec
bit-bang rate, this takes ~1.5 ms per poll. At 100 Hz polling, total SPI
bandwidth is ~600 bytes/sec, well within capacity.

## BBC Micro Test Program (SPIMOUSE)

### Polling Rate

100 Hz, synchronised to the MOS centisecond clock via OSWORD 1. The program
spins on the low byte of the 5-byte timer until it changes.

### Display Rate

10 Hz (every 10th poll). Uses VDU 31,X,Y to position the cursor for in-place
updates in MODE 7. No scrolling.

### Display Layout

```
SPItFIRE Mouse Test

dX=+03  dY=-01

X=04D2  Y=0567

Buttons: L - M
```

### Accumulation

The BBC maintains 16-bit signed totals, adding the sign-extended 8-bit deltas:

```
total_x (16-bit) += sign_extend(mouse_dx)
total_y (16-bit) += sign_extend(mouse_dy)
```

## Memory Budget

### AVR Flash

| Item | Size |
|------|------|
| 5 remap tables (PROGMEM) | 640 B |
| 5 button tables (PROGMEM) | 640 B |
| dx_table + dy_table (PROGMEM) | 512 B |
| Code | ~300 B |
| **Total** | **~2100 B** (1.6% of 128 KB) |

### AVR SRAM

| Item | Size |
|------|------|
| Active remap table | 128 B |
| Active button table | 128 B |
| Accumulators + state | 6 B |
| **Total** | **~262 B** (1.6% of 16 KB) |

### AVR Firmware

```bash
cd firmware
cmake --preset release
cmake --build --preset release --target spimouse
cmake --build --preset release --target upload_spimouse
```

```bash
cd beeb/spitest
make SPIMOUSE
```

Load the resulting `build/SPIMOUSE` file onto the BBC Micro.
